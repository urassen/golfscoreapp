# 詳細設計(版0.4.0まで)

基本設計仕様書(Notion)を、ファイルと関数の単位まで具体化したものです。
段階1(0.1.x)は端末内だけで動く部分、段階2(0.2.0)は手動のバックアップと復元です。オフライン対応(段階3)と自動バックアップ(後回し)は含みません。

## 1 ファイルと役割

公開するのは `public/` の中だけです(Cloudflareの設定は `wrangler.jsonc`)。

| ファイル | 役割 | 画面に依存 |
| --- | --- | --- |
| `public/index.html` | 入れ物。本体が動かなかったときの案内を出す | - |
| `public/style.css` | 見た目(明るい画面と暗い画面の両方) | - |
| `public/js/app.js` | 起動、下のタブ、URLの `#` による画面の切り替え | する |
| `public/js/ui.js` | 短い通知、確認ダイアログ、入力シート、保存つきの変更(`trySave`) | する |
| `public/js/store.js` | localStorage の読み書き。メモリ上の `state` を1つ持つ | しない |
| `public/js/schema.js` | 版の読み替え、空のデータ、`AppError` | しない |
| `public/js/importer.js` | 取り込みの10段階 | しない |
| `public/js/model.js` | ホールの値の読み書き、合計 | しない |
| `public/js/stats.js` | 統計の計算、絞り込み | しない |
| `public/js/charts.js` | SVG のグラフ | しない |
| `public/js/backup.js` | バックアップのファイルの作成と読み取り | しない |
| `public/js/util.js` | エスケープ、名前の正規化、クラブと方向の表、アプリの版 | しない |
| `public/js/screens/*.js` | 各画面 | する |

依存の向き: `screens` → `importer` / `stats` / `charts` / `ui` → `store` / `schema` / `model` / `util`。

## 3 データ

端末内のデータは、基本設計仕様書の「1 データ設計」のとおりです。保存キーは `golf.data`(本体)、`golf.rollback`(復元前の控え)、`golf.settings`(設定。今は `lastBackupAt` だけ)です。

- 変更は `store.update(fn)` で行います。`state` のコピーに変更を入れ、保存に成功したときだけ差し替えます。保存に失敗したら `state` は元のままです。
- 保存データが読めないとき(壊れている、アプリより新しい版)は、その理由を出して止まります。上書きはしません。

### 取り込みの下書き(確認画面で直すあいだのデータ)

```
draft
├─ date, facility, nines
├─ allHoles [ { no, par, yard, strokes{self,p1,…}, self{…}, check[項目名] } ]
├─ holeCount            … 9に直すと、前の9ホールだけが対象
├─ players [ { key, name, self, sel } ]   … sel = 同伴者のid / 'new' / 'skip'
├─ printedTotals { key: 合計 }
├─ courseSel            … コースのid / 'new'
└─ dupChoice, totalAck, mismatchAck, fixCourse … 警告への答え
```

`check` の項目名は、`s:<プレーヤーのキー>`(打数)、`club`、`direction`、`bunker`、`ob`、`putt`、`penalty`、`no`、`par`、`yard` です。

## 4 取り込みの処理(`importer.js`)

| 段階 | 関数 | 内容 |
| --- | --- | --- |
| 1〜4 | `parseImport(text)` | JSON の部分を取り出して読む。種類、版、必須項目を確かめ、下書きを返す |
| 5・6 | `prepareDraft(state, draft)` | コースと同伴者を照合する。コースが見つかれば、空欄のパー・ヤード数を埋める |
| 7〜9 | `issues(state, draft)` | 要確認の数、同伴者4人以上、二重取り込み、合計の不一致、コースの不一致を調べ、登録できるかを返す |
| 10 | `register(state, draft)` | コース・同伴者の新規登録と、ラウンドの登録。登録したラウンドの id を返す |

基本設計から具体化した点:

- 貼り付けた文字の前後に説明文や ``` があっても、最初の `{` から最後の `}` までを読みます。
- バックアップのデータ(`golf-backup`)を貼ったときは、バックアップ・リストアの画面へ案内します。
- 自分の打数は必須です。同伴者の打数が空のホールは、要確認にします。
- クラブや方向が表に当てはまらないときは、空欄にして要確認にします。
- `bunker` は回数です。`true` / `false` で来たときは 1 / 0 に直します。
- 話し忘れた項目(`null`)は空欄のままで、要確認にはしません。
- 印刷された合計との照合は、ホール数を直していないときだけ行います。
- 「コースを直す」を選ぶと、登録のときに、登録済みコースのパー・ヤード数を取り込みデータに合わせます。過去のラウンドは変わりません。

## 5 統計(`stats.js`)

- `filterRounds(state, { holeCount, courseId, period })` … 新しい順に並べて絞り込みます。
- `summarize(rounds)` … 平均、ベスト、パット平均、3パット、パー別の平均、内訳、FWキープ率、パーオン率(推定)を返します。`lines` はグラフ用で、古い順です。
- パットが1ホールでも空欄のラウンドは、パット合計を「不明」にします。パット平均からも除きます。
- FWキープ率の分母は、パー4・5のうち方向が入っているホールです。
- パーオン率(推定)の分母は、パット数が入っているホールです。打数−パット数 が パー−2 以下ならパーオンと数えます。

## 6 バックアップと復元(版0.2.0)

- 「バックアップする」: `makeBackup` で `{ type: 'golf-backup', schema, createdAt, appVersion, data }` を作り、`navigator.share` で共有シートを開きます。共有できない端末ではダウンロードに切り替えます。共有シートを閉じたとき(`AbortError`)は、最終バックアップの日時を変えません。共有シートはボタンを押した操作の中で開く必要があるので、待たずに呼びます。
- 「ファイルを選んで戻す」: `input type=file` で選び、`readBackup` で種類と版を確かめて最新の版に読み替えます。確認ダイアログのあと `store.restore` で置き換えます。
- `store.restore` は、今の保存データを、読めないものも含めて文字のまま `golf.rollback` に退避します。保存データが読めずにアプリが止まっているときも、バックアップ・リストア画面からは復元できます。
- 「復元を取り消す」(`store.undoRestore`): 控えの文字に戻し、控えを消します。初めての端末で復元したときは、空の状態に戻ります。
- 「バックアップが古い」: ラウンドが1件以上あり、最終バックアップがないか7日以上前のとき。ホームに帯を出し、帯の「バックアップする」でそのまま共有シートを開きます。

## 7 まとめ取り込み(版0.3.0、R010)

- `parseImportAll(text)`: `golf-rounds`(まとめ)と `golf-round`(1件)の両方を読み、ラウンドごとに `{ draft }` か `{ error }` を返します。全体が読めないとき(JSONでない、版が新しい、`rounds` が空)は例外にします。各ラウンドの版は、ラウンドに `schema` がなければ全体の `schema` を使います。
- 1件だけなら今までどおり確認画面(`#/confirm`)、2件以上なら `#/batch` を開きます。下書きは `draftbox.js` の `box.batch` に `[{ no, draft } | { no, error }]` で持ちます(`no` は貼り付けたときの番号)。
- 一覧の状態は `batch.js` の `itemStatus`: 取り込みの中の重複(`batchDuplicateOf`)、要確認、空欄、同伴者4人以上、コースの違い、合計の違い、登録済みとの重複の順に見ます。
- `registerBatch(state, items)`: 1回の保存の中で、登録できるラウンドを順に登録します。各ラウンドの登録前に `rematch` で、前のラウンドで新規登録したコース・同伴者に付け直します(同じコースが2つできない)。下書きはコピーして使い、書き換えません。
- 登録のあと、残ったラウンドにも `rematch` をかけます。これで、今登録したラウンドとの重複が「同じラウンドが既にあります」として出ます。
- まとめ取り込みの確認画面で重複の帯の「中止」を押すと、そのラウンドだけ一覧から外します。

## 8 履歴の絞り込み(版0.3.0、R011)

- `filterHistory(state, { companionIds, year })`: 選んだ同伴者全員を含むラウンド(ほかの人がいてもよい)と、年で絞り込み、新しい順で返します。
- 条件は `history.js` のモジュールの中に持ちます。アプリを開いている間だけ残り、開き直すと解除されます。削除された同伴者や、ラウンドのない年は、条件から自動で外します。

## 9 クラブ管理(版0.3.0、R012)

- クラブの一覧は全データの `clubs` に持ちます(バックアップに含まれる)。ないデータには、版0.2.0までの14種類(`DEFAULT_CLUBS`)を入れます。データ形式の版は1のままです。
- `#/clubs`(`screens/clubs.js`): 登録済みのクラブを並べ、×で外します。候補(`CLUB_CANDIDATES`)から足すか、名前を入れて足します。並びは候補の順で、候補にない名前は後ろ(`sortClubs`)。
- 照合(`findClub`)は全角半角・大文字小文字・空白を無視します(u5 → U5)。
- 取り込みでは、クラブを書いてあるとおりに受け取り、`prepareDraft` の中の `checkClubs` で登録済みのクラブと照合します。登録にないクラブは値を残したまま要確認にします。「-」は記録なし(空欄)にします。
- 入力シートのクラブの選択肢は、登録済みのクラブです。今の値が登録にないときも、選択肢に出します。

## 10 Claude用の指示文(版0.3.0、R013)

- 自分の項目(クラブ・方向・バンカー・OB・パット・ペナルティ)は、画像にあれば画像を優先し、なければ音声メモから読みます。
- GDOのスコア一覧の表記の読み替えと、同じラウンドの画像を1つにまとめる決まりを書いています(`docs/Claude用の指示文.md`)。

## 11 スコア推移のグラフの数字と平均の線(版0.4.0、R014)

- `stackedBars(items, { mini, avgTotal, avgPutt })`: 平均があれば、横の点線を引きます(合計=`c-avg`、パット=`c-pavg`)。統計のグラフでは右に34の余白を取り、そこに平均の数字を出します。ホーム(`mini`)は線だけです。
- 棒の中の数字: 棒の太さが14以上で、区切りの高さが13以上のときだけ、「それ以外」とパットの数を出します。棒が多くて細いときは出しません。
- 棒の上の合計の数字には縁取りを付け、平均の線が重なっても読めるようにします。棒が多いとき(1本の幅が18未満)は文字を小さくします。
- 平均は統計の `summarize` の `avg` と `puttAvg` です(パット不明のラウンドはパットの平均から外す)。
