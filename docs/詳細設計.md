# 詳細設計(版0.1.0・段階1)

基本設計仕様書(Notion)を、ファイルと関数の単位まで具体化したものです。
段階1は「端末内だけで動く部分」です。Googleドライブ連携(段階2)とオフライン対応(段階3)は含みません。

## 1 ファイルと役割

公開するのは `public/` の中だけです(Cloudflareの設定は `wrangler.jsonc`)。

| ファイル | 役割 | 画面に依存 |
| --- | --- | --- |
| `public/index.html` | 入れ物。本体が動かなかったときの案内を出す | - |
| `public/style.css` | 見た目(明るい画面と暗い画面の両方) | - |
| `public/js/app.js` | 起動、下のタブ、URLの `#` による画面の切り替え | する |
| `public/js/ui.js` | 短い通知、確認ダイアログ、入力シート、保存つきの変更(`trySave`) | する |
| `public/js/store.js` | localStorage の読み書き。メモリ上の `state` を1つ持つ | しない |
| `public/js/schema.js` | 版の読み替え、空のデータ、`AppError` | しない |
| `public/js/importer.js` | 取り込みの10段階 | しない |
| `public/js/model.js` | ホールの値の読み書き、合計 | しない |
| `public/js/stats.js` | 統計の計算、絞り込み | しない |
| `public/js/charts.js` | SVG のグラフ | しない |
| `public/js/util.js` | エスケープ、名前の正規化、クラブと方向の表、アプリの版 | しない |
| `public/js/screens/*.js` | 各画面 | する |

依存の向き: `screens` → `importer` / `stats` / `charts` / `ui` → `store` / `schema` / `model` / `util`。

## 2 画面とURL

| URL | 画面 | ファイル |
| --- | --- | --- |
| `#/home` | ホーム | `screens/home.js` |
| `#/history` | 履歴 | `screens/history.js` |
| `#/round/{id}` | ラウンド詳細(編集・削除) | `screens/detail.js` |
| `#/import` | 取り込みの貼り付け | `screens/import.js` |
| `#/confirm` | 取り込みの確認 | `screens/confirm.js` |
| `#/stats` | 統計 | `screens/statsview.js` |
| `#/settings` | 設定 | `screens/settings.js` |
| `#/courses` `#/course/{id または new}` | コース管理 | `screens/courses.js` |
| `#/companions` `#/companion/{id または new}` | 同伴者管理 | `screens/companions.js` |
| `#/backup` | バックアップ・リストア(この版は案内だけ) | `screens/backup.js` |

- 各画面は `render(引数)` で HTML の文字列を返します。画面を開くたび、値が変わるたびに全体を作り直します。
- 操作は `#view` の1か所で受け、いまの画面の `onClick` / `onInput` / `onChange` に渡します。
- 画面を移ったときだけ `enter()` を呼び、編集中の内容を捨てます。
- 画面に出す文字列は、必ず `esc()` を通します。

## 3 データ

端末内のデータは、基本設計仕様書の「1 データ設計」のとおりです。保存キーは `golf.data` です(`golf.rollback` と `golf.settings` は段階2から使います)。

- 変更は `store.update(fn)` で行います。`state` のコピーに変更を入れ、保存に成功したときだけ差し替えます。保存に失敗したら `state` は元のままです。
- 保存データが読めないとき(壊れている、アプリより新しい版)は、その理由を出して止まります。上書きはしません。

### 取り込みの下書き(確認画面で直すあいだのデータ)

```
draft
├─ date, facility, nines
├─ allHoles [ { no, par, yard, strokes{self,p1,…}, self{…}, check[項目名] } ]
├─ holeCount            … 9に直すと、前の9ホールだけが対象
├─ players [ { key, name, self, sel } ]   … sel = 同伴者のid / 'new' / 'skip'
├─ printedTotals { key: 合計 }
├─ courseSel            … コースのid / 'new'
└─ dupChoice, totalAck, mismatchAck, fixCourse … 警告への答え
```

`check` の項目名は、`s:<プレーヤーのキー>`(打数)、`club`、`direction`、`bunker`、`ob`、`putt`、`penalty`、`no`、`par`、`yard` です。

## 4 取り込みの処理(`importer.js`)

| 段階 | 関数 | 内容 |
| --- | --- | --- |
| 1〜4 | `parseImport(text)` | JSON の部分を取り出して読む。種類、版、必須項目を確かめ、下書きを返す |
| 5・6 | `prepareDraft(state, draft)` | コースと同伴者を照合する。コースが見つかれば、空欄のパー・ヤード数を埋める |
| 7〜9 | `issues(state, draft)` | 要確認の数、同伴者4人以上、二重取り込み、合計の不一致、コースの不一致を調べ、登録できるかを返す |
| 10 | `register(state, draft)` | コース・同伴者の新規登録と、ラウンドの登録。登録したラウンドの id を返す |

基本設計から具体化した点:

- 貼り付けた文字の前後に説明文や ``` があっても、最初の `{` から最後の `}` までを読みます。
- バックアップのデータ(`golf-backup`)を貼ったときは、バックアップ・リストアの画面へ案内します。
- 自分の打数は必須です。同伴者の打数が空のホールは、要確認にします。
- クラブや方向が表に当てはまらないときは、空欄にして要確認にします。
- `bunker` は回数です。`true` / `false` で来たときは 1 / 0 に直します。
- 話し忘れた項目(`null`)は空欄のままで、要確認にはしません。
- 印刷された合計との照合は、ホール数を直していないときだけ行います。
- 「コースを直す」を選ぶと、登録のときに、登録済みコースのパー・ヤード数を取り込みデータに合わせます。過去のラウンドは変わりません。

## 5 統計(`stats.js`)

- `filterRounds(state, { holeCount, courseId, period })` … 新しい順に並べて絞り込みます。
- `summarize(rounds)` … 平均、ベスト、パット平均、3パット、パー別の平均、内訳、FWキープ率、パーオン率(推定)を返します。`lines` はグラフ用で、古い順です。
- パットが1ホールでも空欄のラウンドは、パット合計を「不明」にします。パット平均からも除きます。
- FWキープ率の分母は、パー4・5のうち方向が入っているホールです。
- パーオン率(推定)の分母は、パット数が入っているホールです。打数−パット数 が パー−2 以下ならパーオンと数えます。

## 6 テスト

- `npm test` … 取り込み、統計、版、保存の自動テスト(`tests/`)。見本のデータは `tests/sample.mjs` で、数字は作ったものです。
- 画面は、iPhoneの画面サイズにしたPCのブラウザで、取り込みから統計までを通して確かめます。実機の確認は別に行います。
