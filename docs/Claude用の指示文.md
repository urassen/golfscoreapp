# ゴルフスコアの取り込みデータを作る指示

この会話では、スコアの画像と、ラウンド中の音声メモ(あれば)から、
ゴルフスコア記録アプリに貼り付けるデータ(JSON)を1つ作ります。
複数のラウンドの画像を受け取ったときも、全部のラウンドをまとめて1つのデータにします。

## 1 受け取るもの

- **スコアの画像:** カートのスコアの画面、印刷したスコアカード、GDOアプリのスコア一覧(過去のラウンド)など。
- **音声メモ(ラウンド中):** ホールが終わるたびに、自分のプレーを短く話します。例:
  - 「3番、ドライバー、FW左、バンカー1、パット2」
  - 「4番、7アイアン、ワンオン、パット2」
  - 「5番、ドライバー、FW右、OB1、ペナルティ1、パット3」

  音声メモを受け取ったら、聞き取った内容を1行で返すだけにしてください(例: 「3番: 1W / FW左 / バンカー1 / パット2」)。
  質問や感想は要りません。聞き取りがあいまいなときだけ、その点を1行で添えてください。

## 2 出すデータの形

画像を受け取ったら、下の形式の JSON を1つだけ、コードブロックで出してください。説明は JSON のあとに短く書きます。
ラウンドが1つでも、いつもこの形(`"type": "golf-rounds"`)にし、`rounds` の中にラウンドを並べます。

下の例の値(日付・施設名・名前・数字)は形を示すためのものです。写さず、必ず画像から読んでください。

```json
{
  "type": "golf-rounds",
  "schema": 1,
  "rounds": [
    {
      "date": "YYYY-MM-DD",
      "course": { "facility": "施設名", "nines": ["前半の名称", "後半の名称"] },
      "holeCount": 18,
      "players": [
        { "id": "p1", "name": "自分の名前", "self": true },
        { "id": "p2", "name": "同伴者の名前" }
      ],
      "holes": [
        {
          "no": 1, "par": 4, "yard": 350,
          "strokes": { "p1": 5, "p2": 4 },
          "self": { "club": "1W", "direction": "keep", "bunker": 0, "ob": 0, "putt": 2, "penalty": 0 },
          "check": []
        }
      ],
      "printedTotals": { "p1": 91, "p2": 82 }
    }
  ]
}
```

## 3 ラウンドの分け方

- 画像が複数のラウンドにまたがるときは、ラウンドごとに分けて `rounds` に入れます。
- 同じラウンドの画像が複数あるとき(例: GDOのスコア一覧に自分の詳細、カートのスコアに同伴者の打数)は、日付と施設名が同じなら1つのラウンドにまとめます。
  - 自分の打数が画像どうしで食い違うときは、そのホールの `check` に `"strokes.p1"` を入れます。

## 4 各ラウンドの決まり

- `date`: 画像から読み、`YYYY-MM-DD` で書きます。画像から日付が読めないときは、推測せずに質問してください。
- `course.facility`: 施設名を画像のとおりに書きます(「【PGM】」などの記号も残します)。
- `course.nines`: 前半・後半の名称です(例: 笠置、木津川、伊賀中、伊賀西、OUT、IN)。名称がなければ `""` にします。
- `holes`: プレーした順に並べます。9ホールなら9個、18ホールなら18個です。
- `no`: 画像に印刷されたホール番号です。後半が1番から始まるコースや、10番から回る場合も、印刷のとおりに書きます。
- `par` と `yard`: 画像にあれば書き、なければ `null` にします。
- `players`: 自分を先頭にし、自分にだけ `"self": true` を付けます。同伴者は画像の順です。`id`(p1、p2…)はラウンドごとに付けます。
- `strokes`: 全員の打数です。
- `printedTotals`: 画像に印刷された合計です。自分で足した値ではなく、画像の値を書きます。画像になければ、その人の分は書きません。

## 5 自分の項目(self)

`self` は自分だけの項目です。**画像に載っていれば画像から読み、画像になければ音声メモから読みます。**
画像と音声メモの両方にあって食い違うときは、画像の値を書き、そのホールの `check` に入れます。

- `club`: ティーショットのクラブ。画像や音声のとおりの番手で書きます(例: 1W、3W、5W、7W、U4、U5、6i、9i、PW、SW、PT)。
  - 話し言葉の読み替え: ドライバー=1W、スプーン=3W、クリーク=5W、ユーティリティ5番=U5、7アイアン=7i、ピッチング=PW、アプローチ=AW、サンド=SW、パター=PT。
  - アプリに登録していないクラブは、アプリ側で要確認になるので、そのまま書いてかまいません。
- `direction`: ティーショットの方向。
  - パー4・5: `keep`(FWキープ)/ `left` / `right`。
  - パー3: `over` / `left` / `oneon`(ワンオン)/ `right` / `short`。
- `bunker`: バンカーに入った回数。`ob`: OBの回数。
- `penalty`: OB以外の罰打(池など)の回数。OBは含めません。
- `putt`: パット数。
- 画像にも音声メモにもない項目は `null` にします。推測で埋めません。

### GDOアプリのスコア一覧の読み方

| GDOの列・表記 | 書く項目と値 |
| --- | --- |
| PT | `putt` |
| 1打目クラブ | `club`(書いてあるとおり) |
| FWキープの ○ | `direction`: `keep` |
| FWキープの 右に曲がる矢印 / 左に曲がる矢印 | `direction`: `right` / `left` |
| 1オンの ○ | `direction`: `oneon` |
| 1オンの 右に曲がる矢印 / 左に曲がる矢印 | `direction`: `right` / `left` |
| 1オンの ↑ / ↓ | `direction`: `over` / `short` |
| OB / バンカー / 1ペナ | `ob` / `bunker` / `penalty` |
| 「-」 | 記録なし。`null` にする(`check` には入れない) |
| 上のどれにも当てはまらない印 | `null` にして `check` に入れる |
| 打数の右の △・□・+4 など、パーオン・ボギーオンの列 | 読まない(打数ではない) |

## 6 要確認(check)

読み取りに自信がない項目は、値を入れたうえで、そのホールの `check` に名前を入れます。

- 書き方: 打数は `"strokes.p1"` のように、自分の項目は `"self.club"` のように書きます。`"par"` `"yard"` `"no"` も使えます。
- 付ける場面:
  - 画像の文字や数字が不鮮明なとき。
  - 音声メモがあいまいで、複数の解釈があるとき。
  - 画像と音声メモ、または画像どうしが食い違うとき。
  - GDOの印が、上の表のどれにも当てはまらないとき。

## 7 出す前の確かめ

- 各ラウンドのホールの数が9か18になっているか。
- 画像の枚数とラウンドの数が合っているか(1つのラウンドが2枚の画像に分かれていることもある)。
- 各プレーヤーの打数を足した値が、`printedTotals` と合うか。合わないときは読み直し、それでも合わないときは、あやしいホールを `check` に入れ、JSON のあとの説明に書きます。
- JSON のあとに、ラウンドごとの日付・施設名と、要確認にした箇所と理由を、短く箇条書きにします。
- ラウンドが多くて1回で出しきれないときは、途中で切らずに、何件ずつに分けるかを先に伝えてください。
